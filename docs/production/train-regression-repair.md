# Train search regression repair

The delivered 1.11.0-build.10 APK removed the original public CT Trains connection and required a `TRANSIT_BASE_URL` that was empty in the artifact. Fresh train searches, station refresh and service reports therefore failed. The native journey test seeded an exact cache entry and masked the missing source. Earlier passing counts are not evidence that fresh searches in that candidate worked.

1.11.1 restores the public CT Trains source for both distributions. A configured backend remains optional for rail and falls back to the public source on failure. Unknown/obsolete source preferences recover to an available source without resetting the encrypted profile, saved places, station preferences or journeys. Results preserve actual source identity and distinguish newly checked schedules from cached information. Direct requests parse only bounded HTML and never execute page scripts. Station/startup checks reuse recently fetched catalogues and reports to limit unnecessary requests.

Choosing a destination before a start now opens the start picker; the search begins after both are chosen. Invalid/same-endpoint selections show an actionable error. Unavailable results have a retry action. Choosing a planned route copies the actual journey date/time into the selected state. The native acceptance test begins with empty query cache, searches the live public source through the actual Home UI, selects a route, and starts foreground guidance. It runs for GitHub/Play debug variants and a GitHub release variant; failure blocks release checks. Separate deterministic contract and encrypted-cache outage tests cover missing/failed backend configuration, cancellation, source identity, unknown pages, and exact-query offline fallback.

Verification is pending until the repair's workflow runs complete. A point-in-time source probe on 2026-10-12 fetched the actual CT Trains station form and Unibell → Salt River schedule for 2026-10-13 at 07:00 and received four journey cards. This standalone probe is not a substitute for native acceptance.

Fresh bus searches still require the owned backend. This repair does not claim to finish production deployment, source access approval, physical phone/Samsung acceptance, account-based sharing or Play Console submission. AI development attribution remains in the repository only.
